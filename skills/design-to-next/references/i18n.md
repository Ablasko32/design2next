# Translations (i18n)

Read only when site needs several languages: user asks, or design shows language switcher / copy in several languages. Never by default.

SKILL.md rules still apply; this adds translations.

## 1. Before starting

Ask (skip what design / user answered):

1. **Which languages**, which is **default**.
2. **URL strategy:** all prefixed (`/en`, `/de`), recommended, or default without prefix (`/`, `/de`).
3. **Translated slugs?** (`/en/about` vs `/de/ueber-uns`) or same slug for all.
4. **Who translates:** user provides, or Claude drafts for review. Drafts always listed for user to check.

Then check Next.js i18n docs (`node_modules/next/dist/docs/` or https://nextjs.org/docs) for current API: `params`, `generateStaticParams`, and whether interceptor file is `proxy.ts` or `middleware.ts` in this version.

## 2. Approach

- **Default: native Next.js dictionaries** (Next.js docs pattern). No extra library. Fits landing pages, most marketing sites.
- **`next-intl`** only if user asks or project truly needs it: many client components with own text, ICU plurals / rich formatting, large app / webshop. Then follow its App Router + Cache Components docs, keep folder rules below.

Rest of file = native approach.

## 3. Structure

```
app/
  [lang]/
    layout.tsx          root layout: <html lang={lang}>, generateStaticParams
    page.tsx
    loading.tsx
    error.tsx
    not-found.tsx
    about/ ...
  sitemap.ts
  robots.ts
  global-error.tsx
proxy.ts                locale detection + redirect (or middleware.ts, check docs)
dictionaries/
  en.json               default language = source of the dictionary type
  de.json
constants/
  i18n.ts               locales, defaultLocale, locale labels
lib/
  i18n/
    get-dictionary.ts   server-only loader
    locale.ts           hasLocale(), helpers for localized paths
```

- Root layout moves to `app/[lang]/layout.tsx` → `<html lang>` always right.
- `global-error.tsx` stays in `app/`, can't know language: short text, default language.

## 4. Config and loader

```ts
// constants/i18n.ts
export const LOCALES = ["en", "de"] as const;
export const DEFAULT_LOCALE = "en";
export type Locale = (typeof LOCALES)[number];

export const LOCALE_LABELS = {
  en: "English",
  de: "Deutsch",
} as const satisfies Record<Locale, string>;
export const OG_LOCALES = {
  en: "en_US",
  de: "de_DE",
} as const satisfies Record<Locale, string>;
```

```ts
// lib/i18n/locale.ts
import { LOCALES, type Locale } from "@/constants/i18n";

export function hasLocale(value: string): value is Locale {
  return (LOCALES as readonly string[]).includes(value);
}
```

```ts
// lib/i18n/get-dictionary.ts
import "server-only";
import type { Locale } from "@/constants/i18n";

const dictionaries = {
  en: () => import("@/dictionaries/en.json").then((m) => m.default),
  de: () => import("@/dictionaries/de.json").then((m) => m.default),
} satisfies Record<Locale, () => Promise<unknown>>;

export type Dictionary = Awaited<ReturnType<(typeof dictionaries)["en"]>>;

export async function getDictionary(locale: Locale): Promise<Dictionary> {
  return dictionaries[locale]();
}
```

- Default language JSON = source of `Dictionary` type. Every other language has **same keys**. Add a typecheck (e.g. `satisfies Dictionary` import in a small file, or a script) so a missing key fails `typecheck`.
- Keys grouped by section: `hero.title`, `footer.links.contact`, `seo.home.title`, `images.hero.main`.

## 5. Routing

`app/[lang]/layout.tsx`:

- `generateStaticParams` returns every locale → all languages prerendered.
- Validate param: unknown locale → `notFound()`.
- Set `<html lang={lang}>`.

Check docs for current `params` shape (recent versions: Promise, `const { lang } = await params`).

`proxy.ts` (or `middleware.ts`): path without locale → redirect to best `Accept-Language` match, fallback `DEFAULT_LOCALE`. Exclude `/_next`, `/api`, static files, `sitemap.xml`, `robots.txt`. "Default without prefix" → rewrite (not redirect) for default language.

## 6. Content rules

These override some SKILL.md rules when i18n is on:

- **Text in dictionaries, not `constants/`.** `constants/` keeps only language-independent data: hrefs, emails, phones, social URLs, image `src`.
- **Navigation:** `constants/navigation.ts` keeps `href` + dictionary key; label from dictionary.
- **Links:** every internal link localized via one helper (`localizedPath(locale, path)`) or small `LocalizedLink`. Never hardcode `/en/...`.
- **Images:** `IMAGES` keeps `src`; `alt` from dictionary (`images.hero.main`).
- **SEO text** (`constants/seo.ts`) moves to dictionary under `seo.<page>`.
- **Client components** get needed strings as props from server. Never ship whole dictionary to client.
- **Forms:** Zod returns message **keys**, not sentences. Form shows translation. Action returns keys too.
- **Numbers, dates, prices:** `Intl.NumberFormat` / `Intl.DateTimeFormat` with current locale. Never by hand.
- Text length varies. Check longest language doesn't break layout.

## 7. Language switcher

- Look / placement from design. Not in design → ask.
- Leaf `"use client"` (needs `usePathname` to keep current page).
- Real links (`next/link`), not JS-only button → crawlable.
- Each option: `lang` + `hrefLang`, label from `LOCALE_LABELS` (each language in its own name).
- Translated slugs → per-page slug map, in one place next to routes, not spread through components.

## 8. SEO

- `generateMetadata` in every page, reads dictionary for its locale. SKILL.md title / description rules apply **per language**.
- `alternates.canonical`: page's own localized URL.
- `alternates.languages`: every language version + `x-default` (→ default language).
- `openGraph.locale` from `OG_LOCALES`, `openGraph.alternateLocale` for others.
- JSON-LD: text in page language, `inLanguage` on `WebSite` / `Article`.
- `sitemap.ts`: one entry per page per language, each with `alternates.languages`.
- `robots.ts`: unchanged; paths excluded in `proxy.ts` must stay reachable.

## 9. Checklist

- [ ] Languages, default, URL and slug strategy agreed with user
- [ ] Root layout in `app/[lang]/`, `<html lang>` right, unknown locale → 404
- [ ] All locales prerendered via `generateStaticParams`
- [ ] Same dictionary keys in every language (typecheck or script)
- [ ] No user-facing text in components / `constants/`. Hrefs + data stay in `constants/`
- [ ] All internal links via one helper, no hardcoded locale in paths
- [ ] Image `alt`, SEO text, form errors translated
- [ ] Switcher: real links with `hrefLang`, keeps current page
- [ ] `hreflang` alternates + `x-default`, localized canonical, OG locale per page
- [ ] Sitemap: every page in every language with alternates
- [ ] Checked in browser, every language, all sizes (longest doesn't break layout)
- [ ] Claude-drafted translations listed for user review
