# Translations (i18n)

Read only when site needs several languages: user asks, or design shows language switcher / copy in several languages. Never by default.

SKILL.md rules still apply; this adds translations.

## 1. Before starting

Ask (skip what design / user answered):

1. **Which languages**, which is **default**.
2. **Translated slugs?** (`/o-nama` + `/en/about`) or same slug for all (`/about` + `/en/about`). User's choice wins. `auto` / no answer → decide by page type (section 5a), list it in summary.
3. **Who translates:** user provides, or Claude drafts for review. Drafts always listed for user to check.

**URL strategy is fixed, don't ask:** default language **without prefix** (`site.com`, `site.com/about`), others prefixed (`site.com/en`, `site.com/en/about`). **No language detection, no redirect by `Accept-Language` / cookie.** Search engines find each language through `hreflang` + sitemap (section 8); people switch with the language switcher.

Then check Next.js i18n docs (`node_modules/next/dist/docs/` or https://nextjs.org/docs) for current API: `params`, `generateStaticParams`, and whether interceptor file is `proxy.ts` or `middleware.ts` in this version.

## 2. Approach

- **Default: native Next.js** (docs i18n pattern) with the `messages/<lang>.json` files that already exist (SKILL.md section 4, Text). No extra library. Fits landing pages, most marketing sites.
- **`next-intl`** only if user asks or project truly needs it: many client components with own text, ICU plurals / rich formatting, large app / webshop. Then follow its App Router + Cache Components docs, keep folder rules below, and keep the URL strategy: `localePrefix: "as-needed"`, `localeDetection: false`.

Rest of file = native approach.

## 3. Structure

```
app/
  [lang]/
    layout.tsx          root layout: <html lang={lang}>, generateStaticParams
    page.tsx
    loading.tsx
    error.tsx
    not-found.tsx
    about/ ...
  sitemap.ts
  robots.ts
  global-error.tsx
proxy.ts                public URL → internal route (rewrite) or one 308 (or middleware.ts, check docs)
messages/
  hr.json               default language = source of the Messages type
  en.json
constants/
  i18n.ts               locales, defaultLocale, locale labels
  routes.ts             ROUTES: path + public slug per locale (section 5a)
lib/
  routing.ts            href(), matchRoute(), pageAlternates() (no server-only)
  i18n/
    messages.ts         server-only loader: getMessages(locale)
    locale.ts           hasLocale()
```

- Root layout moves to `app/[lang]/layout.tsx` → `<html lang>` always right.
- `global-error.tsx` stays in `app/`, can't know language: short text, default language.
- With CMS (Payload): `app/(frontend)/[lang]/`; content translated through Payload `localization` (`references/cms.md`), UI text still in messages.

- Keys grouped by section: `hero.title`, `footer.links.contact`, `seo.home.title`, `images.hero.main`.

## 5. Routing

`app/[lang]/layout.tsx`:

- `generateStaticParams` returns every locale → all languages prerendered.
- Validate param: unknown locale → `notFound()`.
- Set `<html lang={lang}>`.

Check docs for current `params` shape (recent versions: Promise, `const { lang } = await params`).

`proxy.ts` (or `middleware.ts`): one function, all URL rules (section 5a code):

- `matchRoute(pathname)` → no match → pass through (Next.js 404).
- Match → build the one correct URL with `href(route, { locale, params })`.
  - Request URL ≠ correct URL → **one 308** to it. Covers `/<default>/...`, slug of another language (`/en/usluge`, `/services` on `hr`), trailing slash.
  - Equal → **rewrite** to internal route `/<locale><path>`. URL in the browser stays public.
- **No `Accept-Language` / cookie detection, no auto-redirect.** Other languages only via switcher links and `hreflang`.

Exclude `/_next`, `/api`, static files, `sitemap.xml`, `robots.txt`, `manifest.webmanifest` and metadata image routes (`opengraph-image`, `twitter-image`, `icon`, `apple-icon`, also nested like `/blog/x/opengraph-image`). Exclude them as whole path segments, never as a substring (a bare `icon` would also skip a page like `/icons-guide`). Exact matcher syntax: check Next.js `proxy` / `matcher` docs, then test root, nested and real look-alike pages.

## 5a. Slugs

**Which strategy** (when user didn't say):

| Pages                                                                                      | Slugs                                            | Why                                                |
| ------------------------------------------------------------------------------------------ | ------------------------------------------------ | -------------------------------------------------- |
| Public, indexed: landing pages, services, about, contact, blog, shop categories / products | **Translated** (`/usluge`, `/en/services`)       | keyword in URL in each language, natural for users |
| Behind login / not indexed: dashboard, account, checkout, admin, API                       | **Same** for all (`/dashboard`, `/en/dashboard`) | no SEO value, simpler code                         |
| Legal pages                                                                                | Translated (`/privatnost`, `/en/privacy`)        | public, linked from footer                         |

Mixed in one project is fine. Slugs: lowercase, kebab-case, ASCII (`o-nama`, not `o-namá`; č/ć/š/ž/đ → c/c/s/z/d), short, keyword from that language.

**How (native):** `ROUTES` from SKILL.md section 4 (Routes), plus a public path per locale.

- `path` = route folder under `app/[lang]/` (pick one naming, e.g. English, keep it).
- Translated route → every locale listed (`hr`, `en`). Same-slug route → no locale fields, `path` is used for all.
- Unique public path per locale. Dynamic segments keep the folder's param names (`[slug]`).

```ts
// constants/routes.ts
import type { Locale } from "@/constants/i18n";

type Path = `/${string}`;

export const ROUTES = {
  home: { path: "/" },
  services: { path: "/services", hr: "/usluge", en: "/services" },
  about: { path: "/about", hr: "/o-nama", en: "/about" },
  post: { path: "/blog/[slug]" }, // slug value itself per locale from CMS
  dashboard: { path: "/dashboard" }, // behind login: same slug
} as const satisfies Record<
  string,
  { path: Path } & Partial<Record<Locale, Path>>
>;

export type RouteKey = keyof typeof ROUTES;
```

```ts
// lib/routing.ts (replaces the one-language version; no "server-only")
import { DEFAULT_LOCALE, LOCALES, type Locale } from "@/constants/i18n";
import { ROUTES, type RouteKey } from "@/constants/routes";

type Params = Record<string, string>;

export function fillPath(pattern: string, params: Params = {}) {
  return pattern.replace(/\[(\w+)\]/g, (_, key: string) => {
    if (params[key] == null) throw new Error(`href: missing param "${key}"`);
    return encodeURIComponent(params[key]);
  });
}

const publicPattern = (route: RouteKey, locale: Locale): string =>
  (ROUTES[route] as Partial<Record<Locale, string>>)[locale] ??
  ROUTES[route].path;

// Public URL of a route in a locale. Default locale has no prefix.
export function href(
  route: RouteKey,
  {
    locale = DEFAULT_LOCALE,
    params,
  }: { locale?: Locale; params?: Params } = {},
) {
  const path = fillPath(publicPattern(route, locale), params);
  if (locale === DEFAULT_LOCALE) return path;
  return path === "/" ? `/${locale}` : `/${locale}${path}`;
}

const MATCHERS = (Object.keys(ROUTES) as RouteKey[]).flatMap((route) =>
  LOCALES.map((slugLocale) => ({
    route,
    re: new RegExp(
      `^${publicPattern(route, slugLocale).replace(/\[(\w+)\]/g, "(?<$1>[^/]+)")}/?$`,
    ),
  })),
);

// Public pathname → route + locale + params. null = unknown URL.
export function matchRoute(pathname: string) {
  const [, first = "", ...rest] = pathname.split("/");
  const prefixed = (LOCALES as readonly string[]).includes(first);
  const locale = (prefixed ? first : DEFAULT_LOCALE) as Locale;
  const path = prefixed ? `/${rest.join("/")}` : pathname;
  for (const { route, re } of MATCHERS) {
    const hit = re.exec(path);
    if (!hit) continue;
    const params = Object.fromEntries(
      Object.entries(hit.groups ?? {}).map(([k, v]) => [
        k,
        decodeURIComponent(v),
      ]),
    );
    return { route, locale, params };
  }
  return null;
}
```

```ts
// proxy.ts (logic; matcher + exclusions per section 5)
const m = matchRoute(request.nextUrl.pathname);
if (!m) return NextResponse.next();
const target = href(m.route, { locale: m.locale, params: m.params });
if (target !== request.nextUrl.pathname) {
  return NextResponse.redirect(
    new URL(target + request.nextUrl.search, request.url),
    308,
  );
}
const path = fillPath(ROUTES[m.route].path, m.params);
const internal = path === "/" ? `/${m.locale}` : `/${m.locale}${path}`;
return NextResponse.rewrite(
  new URL(internal + request.nextUrl.search, request.url),
);
```

- `href` builds every link, `redirect()`, canonical, hreflang, sitemap URL, switcher target. Never a hand-written path.
- Dynamic CMS slugs (posts, products): route pattern same for all locales; the **value** differs per locale and comes from the CMS slug map (section 9). Wrong-language slug value → page looks it up, `permanentRedirect` to the right one or `notFound()`.
- Same-slug project (user's choice): no locale fields anywhere; `href` only adds / drops the prefix.
- **Every page route is in `ROUTES`** (unknown URLs pass through and must 404).
- Test after build: each public URL 200, each wrong spelling one 308, `scripts/check-i18n-seo.mjs` (section 8).

## 6. Content rules

On top of SKILL.md section 4 (Text) when i18n is on:

- **Text in messages, not `constants/`** (same as one-language rule). `constants/` keeps only language-independent data: hrefs, social URLs, image `src` (contact data from env).
- **Navigation:** `constants/navigation.ts` keeps route key + message key (`{ route: "services", label: "nav.services" }`); URL from `href`, label from messages.
- **Links:** every internal link via `href(route, { locale, params })` (section 5a). Never hardcode `/en/...` or a slug.
- **Images:** `IMAGES` keeps `src`; `alt` from messages (`images.hero.main`).
- **SEO text** in messages under `seo.<page>`, per language.
- **Client components** get needed strings as props from server. Never ship whole messages file to client.
- **Forms:** Zod returns message **keys**, not sentences. Form shows translation. Action returns keys too.
- **Numbers, dates, prices:** `Intl.NumberFormat` / `Intl.DateTimeFormat` with current locale. Never by hand.
- Text length varies. Check longest language doesn't break layout.

## 7. Language switcher

- Look / placement from design. Not in design → ask.
- Leaf `"use client"`: `usePathname()` gives the **public** URL → `matchRoute()` turns it into route + params → `href(route, { locale: other, params })` per language. Never swap the prefix by string.
- Dynamic CMS pages (slug differs per locale): page passes its slug map (`{ hr: "cevapi", en: "cevapi-en" }`) to the switcher, which uses it instead of the current param. Missing language → that option links to that language's home (or is hidden), never to a 404.
- Same `matchRoute()` gives the active nav item (compare route keys, not strings).
- Real links (`next/link`), not JS-only button → crawlable.
- Each option: `lang` + `hrefLang`, label from `LOCALE_LABELS` (each language in its own name).

## 8. SEO

Every rule of `references/seo.md` applies **per language**. Plus:

**SEO text per language, not a word-for-word copy**

- Each language has own `seo.<page>.title`, `description`, `keyword` in its messages file. Written for how people search **in that language / market** (keyword that country uses), not a literal translation. Length rules (title 50–60, description 140–160) checked per language.
- Main keyword per page **per language** reported in final summary.
- Claude-drafted SEO text listed for user review like other translations.

**Metadata (`generateMetadata` in every page, reads messages for its locale)**

- `alternates.canonical`: page's **own** localized URL (`/about` for default, `/en/about`). Never points to another language.
- `alternates.languages`: **every** language version of this page (incl. itself) + `"x-default"` → default language URL (unprefixed). Same map on every language version (hreflang must be reciprocal).
- Page missing in a language → leave that language out of the map (never point to a 404 or the default copy).
- `openGraph.locale` from `OG_LOCALES`, `openGraph.alternateLocale` = other locales, `openGraph.url` = localized canonical.
- One helper builds both (`pageAlternates` in `lib/routing.ts`), used by metadata **and** sitemap → can't drift.

```ts
// lib/routing.ts (part)
// paramsFor(locale) → params of this page in that locale, or null = no translation
export function pageAlternates(
  route: RouteKey,
  locale: Locale,
  paramsFor: (l: Locale) => Params | null = () => ({}),
) {
  const languages: Record<string, string> = {};
  for (const l of LOCALES) {
    const params = paramsFor(l);
    if (params) languages[l] = href(route, { locale: l, params });
  }
  if (languages[DEFAULT_LOCALE])
    languages["x-default"] = languages[DEFAULT_LOCALE];
  return {
    canonical: href(route, { locale, params: paramsFor(locale) ?? {} }),
    languages,
  };
}

// Static page:  pageAlternates("services", locale)
// CMS page:     pageAlternates("post", locale, (l) => (slugs[l] ? { slug: slugs[l] } : null))
```

**Sitemap (`app/sitemap.ts`)**

- One entry **per page per language**, `url` absolute (`NEXT_PUBLIC_SITE_URL` + localized path).
- Each entry has `alternates.languages` with **all** language versions + `x-default` (absolute URLs), same map as metadata. Next.js renders them as `<xhtml:link rel="alternate" hreflang>`.
- Translated slugs → real slug per language from the slug map, never the default slug with a prefix.
- After build: open `/sitemap.xml`, check every `<url>` has all `hreflang` links + `x-default`.

```ts
// app/sitemap.ts (part)
const STATIC_ROUTES: RouteKey[] = ["home", "services", "about"];
const abs = (path: string) =>
  new URL(path, envPublic.NEXT_PUBLIC_SITE_URL).href;

return STATIC_ROUTES.flatMap((route) =>
  LOCALES.map((locale) => {
    const { canonical, languages } = pageAlternates(route, locale);
    return {
      url: abs(canonical),
      lastModified,
      alternates: {
        languages: Object.fromEntries(
          Object.entries(languages).map(([l, p]) => [l, abs(p)]),
        ),
      },
    };
  }),
);
// + CMS pages: per published doc, per locale it exists in, with its slug map
```

**JSON-LD**

- Text (`name`, `description`, `headline`, breadcrumbs) in page language from messages.
- `url` = localized canonical of this page. `inLanguage` (BCP 47: `hr`, `en`) on `WebSite`, `WebPage`, `Article`.
- Same entity in every language = **same `@id`** (`${SITE_URL}/#organization`, `${SITE_URL}/#website`), so Google sees one organization, not one per language.
- `BreadcrumbList` items use localized URLs and labels.

**OG image**

- Image with text → one per language (`app/[lang]/opengraph-image.tsx` reads `lang`), `alt` from messages. Image without text → one shared is fine.

**URL setup must not hurt SEO**

This setup (default on `/`, others prefixed, translated slugs via proxy rewrite) is SEO-safe only when:

- **One URL per page per language.** Every other spelling → **one** 308 to it: `/<default>/...`, wrong-language slug, internal folder name, trailing slash variant (pick one `trailingSlash` setting). Never a redirect chain (A → B → C).
- **Rewrite, not redirect,** for the real URLs: `/usluge` answers 200 itself. Bots and people get the **same** response (no user-agent / IP / language based rewrites = no cloaking).
- **Everything points to final URLs:** internal links, canonical, hreflang, sitemap, OG `url`, JSON-LD `url`, switcher. Never to a URL that redirects. All absolute in metadata / sitemap (`metadataBase` + `NEXT_PUBLIC_SITE_URL`).
- **Each hreflang URL** answers 200, is in the sitemap, is its own canonical, has the right `<html lang>`, links back (reciprocal). Codes valid (`hr`, `en`, or `en-GB`); `x-default` → default language.
- **No `noindex`** on language versions, no `robots.ts` rule blocking a language prefix.
- **Missing translation → 404** (and left out of hreflang / sitemap), never a redirect to the default language or a default-language copy on the other URL.
- Pages stay **prerendered** with the proxy (rewrite only picks the route; `generateStaticParams` per locale). Check build output: language pages static, not dynamic.
- `usePathname()` on the client shows the public URL (`/usluge`), not the internal route → switcher / active nav go through `matchRoute()` (section 7), never string parsing.

**Verify (production build, after `check.sh`):**

```bash
<pm> run build && <pm> run start
node <this skill's dir>/scripts/check-i18n-seo.mjs http://localhost:3000
```

Reads `/sitemap.xml` (or the `Sitemap:` lines in `robots.txt`, or a path given as 2nd argument; sitemap index from `generateSitemaps` followed) and checks every URL: 200 without redirect, self canonical, `<html lang>` = hreflang, page hreflang = sitemap alternates, `x-default`, reciprocal, `/<default>/...` → 308. Fix every ERROR.

**Robots**

- `robots.ts`: unchanged, one sitemap URL; paths excluded in `proxy.ts` must stay reachable.

## 9. With CMS (Payload)

Two kinds of text, two places:

- **UI text** (buttons, labels, nav, form errors, fixed sections) → messages (sections 3–6).
- **Content** editors change (posts, pages, products, globals like footer text) → **Payload localization**.

Same locales everywhere: `constants/i18n.ts` is the single source, also for Payload.

```ts
// payload.config.ts (part)
import { en } from "@payloadcms/translations/languages/en";
import { hr } from "@payloadcms/translations/languages/hr";
import { DEFAULT_LOCALE, LOCALES, LOCALE_LABELS } from "./constants/i18n";

localization: {
  locales: LOCALES.map((code) => ({ code, label: LOCALE_LABELS[code] })),
  defaultLocale: DEFAULT_LOCALE,
  fallback: true,
},
i18n: { supportedLanguages: { hr, en } }, // admin UI language only (check available languages)
```

Fields:

- `localized: true` on translatable fields only: title, slug (if translated slugs), excerpt, rich text, SEO meta, media `alt`.
- **Not** localized: dates, prices, stock, relations, image files, flags.
- Translated slugs (question 2 in section 1, section 5a) → `slug` localized, unique per locale (check docs). Same slugs → `slug` not localized.
- Turning localization on for existing data changes DB tables → migration + backup (`references/database.md`).

Reads (`references/cms.md` section 4), locale is an argument = part of cache key:

```ts
export async function getPostBySlug(slug: string, locale: Locale) {
  "use cache";
  cacheLife("hours");
  cacheTag(cacheTags.posts(locale), cacheTags.post(slug, locale));

  const payload = await getPayload({ config });
  const { docs } = await payload.find({
    collection: "posts",
    locale,
    fallbackLocale: false, // articles: no silent default-language copy (see below)
    where: { slug: { equals: slug }, _status: { equals: "published" } },
    limit: 1,
  });
  return docs[0] ?? null;
}
```

- **Fallback:** agree with user. Default: globals / short UI-like content fall back to default language; articles / pages **don't** (missing translation → `notFound()` and not in sitemap / hreflang, no duplicate content).
- `cacheTags` take locale (`post(slug, locale)`). Revalidate hooks: revalidate `req.locale`; unknown / all → loop over `LOCALES`.
- **Hreflang + switcher with translated slugs:** read slugs of all locales once (`locale: "all"`, `select: { slug: true }` → `{ hr: "...", en: "..." }`). Use for `pageAlternates(..., (l) => ...)`, sitemap, and pass the map as prop to the language switcher.
- `generateStaticParams`: every locale × its published slugs.
- Routes: `app/(frontend)/[lang]/...` (Payload admin stays in `app/(payload)/`, not localized by URL).
- Claude-drafted content translations entered in Payload are listed for user review, like message drafts.
